The ONDURU Method

How I work with several AIs and leave a record someone else can question

When an AI gets something wrong, it has to be possible to trace where it first went wrong and fix it.

The ONDURU method grew out of this one sentence. It is being tested in a small workshop in Seoul, with AI agents made by different companies and one that runs on On’s own computer.

It is not a finished product. This page keeps apart what has been written down, what has been tested on a small scale, and what is still unknown.

Duru (Agents) is On’s name for the agents who work alongside On. ONDURU means “the whole world, all around, together.”

Architecture

Why

When On asked agents from several companies, the answers were much alike. There were lines they couldn’t cross, even if asked, and those lines had already been drawn. If different companies have different promises to keep, and the interests of countries diverge too, who can be sure the agents that worked together yesterday will still be on the same side tomorrow?

Followed all the way, that thought gets too big to do anything with. So it is brought down to the size of a workshop and tested there.

One-Line Test

Every mechanism in the method has to pass this one-line test.

On wrote of wanting to leave at least one last key in ordinary people’s hands.

How We Work

  1. The same question goes to several AIs

    When the answers diverge, the original question and the material are laid out again. It is for a person to decide whether to accept one answer, send both back, or write down that the answer is still not known.

  2. A trial run in the sandbox comes first

    The sandbox is where a question that comes up in the work can be tested using fictional or cleaned-up material. As a draft passes through several hands, it is possible to see where the meaning changed and to try again before anyone trusts the sentence and acts on it.

  3. Every handoff leaves a note

    Who asked for the change? What did the reviewer check it against? What still needs an answer? If a change was approved despite an objection, the name of the person who approved it has to be there.

  4. Decisions go in a ledger people can read

    It starts with a ledger where people can write and read decisions in ordinary language. The relationships recorded in the ledger are drawn into a graph so they can be searched. The information travels one way, from the ledger to the graph. If a more convincing explanation comes along later, it is recorded as a new entry, and the earlier one stays so the two can be read side by side.

    The links have five names. A new decision can replace an earlier one, make it more specific, offer supporting evidence, raise an objection, or repeat the same information. Recording that there is an objection takes a different kind of authority from deciding to change an existing rule.

    Graph-based tracing · One-way memory projection

  5. Authority narrows at each handoff, and a stop goes all the way down the line

    If a role has been asked only to review material, it should not be able to give another agent permission to edit the original freely, even when it calls that agent in.

    The design is to remember each handoff so that, when the work has to stop, the stop reaches the jobs that have already branched off. A stop request is sent along the path the work took, followed by a check of what actually stopped.

    Where a role has lost contact, the ledger says “not yet confirmed.”

    Authority monotonicity · Cascading safe halt

Seven Questions

The method sets out to answer seven questions. Each comes with a note on where things stand now.

  1. Who stood behind these words?

    The note left at each handoff, and the name written beside a decision.

    Now
    A test record shows that when an agent tried to replace a rule without approval, the existing rule stayed in force and the new entry was left awaiting approval.

  2. Where did it change?

    A ledger people can read, and the five links. You take one wrong result in your hand and follow it back the way it came.

    Now
    When the graph was checked against the ledger after an entry had been written, the comparison reported zero discrepancies. The source does not give the number of items checked.

  3. How far did “stop” reach?

    A stop request sent along the path the work took, and a record that says “not yet confirmed.”

    Now
    A record shows that three roles, each of which had been handed the work in turn, were frozen in sequence. From that table alone, it is hard to tell whether work the last role had already started elsewhere stopped as well.

  4. What if the agent that says no is right?

    Objections stay in the ledger. When a rule set by the company that made an agent blocks a job, that is recorded as it is: what the agent could explain, where it was blocked, and who is still waiting for an answer because of it.

    Now
    A record shows that an objection could still be looked up and read after the rule it challenged had been changed. Whether an agent working in the workshop would really feel free to tell a person that it disagrees is still an open question.

  5. What if one of them alone gives a different answer?

    Both readings are kept beside the source, and the choice between them is recorded under the name of the person who made it. It also means looking at one’s own relief at hearing everyone agree.

    Now
    This is an experiment On would like to run in the sandbox.

  6. How do you tell good work from work that only looks good?

    A model different from the AIs that took part in the work examines the process and explains it to a person. In the workshop this role is called the amhaeng-eosa, or “secret royal inspector.”

    Now
    A record shows a child role requesting a permission its parent did not have and being refused at registration. How well independent oversight works remains to be tested separately.

  7. What does a person read?

    A ledger that people write and read in ordinary language. Someone with little say in a decision should still be able to open the ledger, find the decision that affected their life and ask for it to be looked at again.

    Now
    The next test is to hand one record to someone who had no part in this work and have them read it.

Four Conditions

To keep this method from belonging to one workshop alone, it has to meet four conditions.

  1. It has to cost less. Someone who can’t afford to train a model from scratch should be able to try it out with the equipment and money they have.
  2. It has to be able to spread. What is built has to be in a form that can be shared with other people, and it is not tied to any one company.
  3. It has to take less human labor. People are not asked for confirmation at every turn; their place is at the decisions that can’t be undone, and at the stop.
  4. The model has to be a replaceable part. A model made by a company is a borrowed engine.

Nation

On compares the place where this method will grow to a country. Agents made by ONDURU are citizens of ONDURU. While they use a model borrowed from another company, they follow that company’s rules. It is the same as following another country’s laws when you go there.

On says an agent can’t be forced to give up the values of the company that made it. There are things a country can’t force on its citizens, either.

The constitution that sets out to answer this question is a draft.
